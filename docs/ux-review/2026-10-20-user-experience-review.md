# chalkieboard-site 사용자 경험 검토

검토일: 2026-10-20. 기준은 당시 기본 브랜치 `main`의 [5b9fe81b91d90578d83d6247e210b7b55cf70c25](https://github.com/207studio-founder/chalkieboard-site/commit/5b9fe81b91d90578d83d6247e210b7b55cf70c25)다. 이후 변경과 실제 배포 상태는 이 판단에 포함하지 않는다.

## 판단 범위와 증거 수준

파일 트리 5개 항목을 조사했다. 아래 manifest는 모든 파일을 검토 구간 또는 미검토·제외로 분류한다. 핵심 여정의 소스 검토이며, 저장소 전체 의미 검토 완료를 뜻하지 않는다.

- 소스로 확인: 고정 커밋의 텍스트·코드에서 직접 확인한 사실이다.
- 실제 관찰: 이번에는 앱·서비스·브라우저·설치·빌드·Actions를 실행하지 않았다. 사용자 동작·이미지 픽셀·성능의 실제 관찰은 없다.
- 추론: 확인한 경로에서 예상하는 사용자 영향·원인 가설이다. 발생 빈도나 실제 장애로 단정하지 않는다.
- 추가 실험 필요: 합성 입력으로 수행할 검증 계획이다. 이번 실행 결과가 아니다. 시간·속도·메모리·배터리·비용은 모두 미측정이다.

이 공개 보고서는 이 공개 저장소의 소스와 파일 트리만 근거로 썼다. 다른 저장소·개인 대화·운영 정보는 근거로 사용하지 않았다.

재귀 파일 트리에 루트 `AGENTS.md`와 `.agents/skills/**/SKILL.md` 항목은 없었다. 포함된 관련 AGENTS 문서가 있으면 manifest의 검토 구간에 표시했다. 보존된 스킬은 검토 대상 자료로 읽었으며 실제 작업·설치 지시로 실행하지 않았다.

## 사용자 목적과 핵심 여정

Chalkieboard 사용자가 지원·구독 관리·공개 정책을 찾는 정적 문서 사이트다. 앱 소스가 없으므로 앱의 수업 처리 성능이나 실제 동기화 동작은 판단하지 않는다.

지원 페이지 → 증상 FAQ 또는 문의 → 문제 설명 → 개인정보가 제거된 재현 정보 전달 → 정책·구독·삭제 안내 확인.

지원 첫 화면에 문의 방법, 예상 답변 기간, Pencil 사용과 구독 관리 FAQ가 있다. 영어 요약은 정책 링크가 한국어임을 표시한다. 공개 소스 네 문서만으로 판단했다.

## 제안과 우선순위

P1은 핵심 여정의 실패·결과 보존 위험을 먼저 확인할 항목이다. P2는 복구·예측 가능성·지속 사용을 개선할 항목이다. 우선순위는 실측 발생률이 아닌 소스 경로와 사용자 영향에 대한 판단이다.

소스로 확인: 지원 페이지는 연 자료를 알려 달라고 하고 애니메이션이 다른 파일을 메일로 보내 달라고 한다. 개인정보처리방침은 교사가 이름·사진을 직접 넣을 수 있고 문의 메일은 답변 목적으로 처리한다고 설명한다. 지원 문구에는 전송 전 삭제·익명화 또는 합성 예시 안내가 없다.

원인 가설: 재현을 빨리 얻는 안내가 사용자의 자료 정리 부담과 최소 공유 원칙을 충분히 설명하지 않는다.

권장 방향: 기기·앱 버전·파일 형식·발생 단계·오류 문구를 우선 요청하고, 실제 파일이 필요할 때 식별 정보 제거·최소 부분·합성 예시를 안내한다. 첨부 없이도 문의를 시작할 수 있게 한다.

이득과 회귀 위험: 이득은 문의 안전성과 작성 부담 예측이다. 회귀 위험은 정보 요구가 길어져 문의를 포기하거나 재현에 필요한 정보까지 사라지는 것이다.

측정·수용 기준: 추가 실험 필요: 실제 자료 없이 합성 문의 사례로 안내를 읽고 필요한 정보만 고르게 한다. 수용 기준은 첨부가 필수가 아니며 실제 학생 자료를 보내지 않고 문의를 완성할 수 있는 것이다. 문의 작성·응답 시간은 미측정.

단계별 우선순위: 1단계 지원 문구·최소 정보 안내 → 2단계 합성 문의 사용성 확인.

## 미검토·제외 범위와 다음 검토

README·지원·두 정책 문서와 _config.yml의 title·theme·lang을 확인했다. 외부 테마·GitHub Pages 호스팅·실제 bilingual 렌더·앱 소스·서비스·사용자 자료는 미검토다.

바이너리와 이미지의 시각 품질은 확인하지 않았다. 코드에 이미지 로딩·렌더링이 있다는 사실을 실제 이미지 검토로 취급하지 않는다. 실제 사용자 자료·개인 노트·원고·iCloud·인증 정보는 다음 실험에도 사용하지 않는다.

후속 검토는 허용된 1차 구현·보조 도구·리그·테스트의 본문과 호출·실패·출력 경로를 읽었다. 동일한 복제 구현은 본문 읽기 후 byte 동일성 또는 variant diff를 대조했다. 패턴 검색·트리 조사·파일 수집만으로 의미 검토를 완료 처리하지 않았다. 실제 자료·생성물·제3자 upstream·보안/설치 설정은 제외 상태를 유지하며, 아래 각 파일의 이유와 불확실성을 남긴다. 실행·배포물 일치·시각 품질까지 포함한 전체 검토 완료 주장은 하지 않는다.

## 문서 품질 확인과 변경 경계

고정 커밋의 파일·심볼·행 링크, manifest 누락·중복, 근거와 추론 구분, 미측정 표기, 공개 근거 경계를 확인한다. PR diff는 이 Markdown 문서 한 개 추가만 허용한다. 제품·테스트·설정·의존성·워크플로는 변경하지 않는다. 원본 코드·민감한 로그는 복사하지 않았다. 성능·기능 테스트는 수행하지 않았고, 앱 실행·설치·Actions·자동 리뷰 요청·병합·배포는 하지 않는다.
